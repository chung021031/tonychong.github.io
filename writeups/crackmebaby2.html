CrackMeBaby2

📅 May 2026 🏆 crackmes.one — igr0t7 🔖 Reverse Engineering

Overview

CrackMeBaby2 is a beginner-friendly 64-bit Windows crackme by igr0t7. It is a two-stage challenge: first find a password hidden behind a layer of XOR obfuscation, then answer a follow-up prompt. The binary also ships with process-list anti-debug and a deliberate fake flag designed to fool anyone reading strings without actually reversing the logic.

Binary: CanYouCrackMeBaby2.exe  |  Arch: x86-64 PE (Windows)

Step 1 — Anti-Debug

Before presenting the password prompt, the binary calls CreateToolhelp32Snapshot and walks the running process list with Process32First / Process32Next. It compares each process name against a hardcoded list of common debuggers: x64dbg.exe, ida.exe, ollydbg.exe, and others. A match triggers a message box and an immediate exit.

The quickest bypass is static analysis — load the binary in IDA without attaching a live debugger. If you need dynamic analysis, patch the conditional jump immediately after the anti-debug routine from jz to jmp to skip the exit path.

Step 2 — Finding main

Open the Strings window (Shift+F12) and search for "Input the pass:". Cross-referencing that string (X) drops you directly inside main.

Step 3 — The Fake Flag

The first check in main is bait. It compares the input to a hardcoded 20-byte string using memcmp: 

if (len == 20 && !memcmp(input, "flag{can-you-crack?}", 20))

Entering this prints "Access Denied". It is a red herring for anyone who found it by grepping strings instead of reading the code flow. The real check is on the else branch.

Step 4 — XOR Obfuscation

If the fake-flag comparison fails, the program enters a loop that XORs every byte of the input with the constant 0x0A, then compares the result to a stored ciphertext: 

for (i = 0; i < len; i++)
    input[i] ^= 0x0A;
if (len == 18 && !memcmp(xored_input, "lfkm0cmx:~'~boacdm", 18))

In the IDA disassembly the XOR shows up as: 

140001e40   xor   byte ptr [rax+rcx], 0Ah

Because XOR is its own inverse, recovering the password is a one-liner — just apply the same key to the ciphertext: 

>>> ''.join(chr(ord(c) ^ 0x0A) for c in "lfkm0cmx:~'~boacdm")
'flag:igr0t-theking'

Password: flag:igr0t-theking

Step 5 — Stage 2

Entering the correct password does not end the challenge. The program responds with "You are good, but..." and then asks: 

Say my name...

The comparison this time is a plain memcmp against a literal string: 

if (len == 5 && !memcmp(input2, "igr0t", 5))
    print("You Win.. (;");

The answer is just the author's handle: igr0t

Full Run

Key Takeaways

  • Process-list anti-debug is easy to bypass statically — no patching needed if you stay in IDA.
  • Fake flags placed on the string-search path are a classic misdirection; always follow the actual code flow.
  • XOR with a single-byte key is trivially reversible once you identify the key in the disassembly.

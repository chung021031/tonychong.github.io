Crackme Rev Easy

U Can't Pass

📅 May 2026 🏆 crackmes.one 🔖 Reverse Engineering

Overview

This is my very first reverse engineering writeup. I wouldn't call it a "challenge" — it's more of an introduction to the process. The crackme is a stripped-down Linux ELF that does nothing but compare a hardcoded value against itself and print a result. Simple as it sounds, working through it is a decent first exercise in reading GDB disassembly output and mentally reconstructing the original C code.

Environment: WSL (Ubuntu)  |  Tools: GDB

Loading the Binary

After navigating to the directory containing the crackme, I attached GDB to it: 

gdb main.out

Then disassembled main to see the full function body: 

disassemble main

Annotated Walkthrough

Going through each instruction and what it actually means:

endbr64
  ; Security marker — marks a valid indirect-call target. No logic, can be ignored.

push %rbp
  ; Save the caller's base pointer onto the stack.
mov %rsp, %rbp
  ; Set up a new stack frame — rbp now points to the top of our frame.
sub $0x10, %rsp
  ; Reserve 16 bytes for local variables.

movl $0x0, -0x4(%rbp)
  ; int a = 0

lea 0xe9a(%rip), %rdi   # 0x2004
  ; Load address of the greeting/prompt string into the first argument register.
mov $0x0, %al
  ; Zero float-arg count — required by x86-64 ABI for variadic calls.
call printf@plt
  ; printf(greeting)

movl $0xa, -0x8(%rbp)
  ; int b = 10

cmpl $0xa, -0x8(%rbp)
  ; Compare b with 10.
je main+62
  ; if (b == 10) jump to main+62 — ALWAYS true, always taken.

; ── Dead code (never reached) ──────────────────────────
lea 0xeab(%rip), %rdi   # 0x2030
call printf@plt
  ; printf(SUCCESS_string)   ← unreachable
jmp main+84
; ───────────────────────────────────────────────────────

; main+62:
cmpl $0xa, -0x8(%rbp)
  ; Compare b with 10 again — still 10.
jne main+82
  ; if (b != 10) jump to main+82 — NEVER true, never taken.

lea 0xe9f(%rip), %rdi   # 0x203a
  ; Load the FAILURE string into the first argument register.
call printf@plt
  ; printf(FAILURE_string)   ← always executes

; main+82 / main+84:
mov -0x4(%rbp), %eax
  ; return a; → return 0
add $0x10, %rsp
  ; Release local variable space.
pop %rbp
  ; Restore caller's base pointer.
ret
  ; Return to caller.

Reconstructed C Code

Translating the assembly back to C makes the logic — and its absurdity — obvious: 

int main() {
    int a = 0;
    int b = 10;

    printf(greeting);       // always printed

    if (b == 10)            // ALWAYS true → jumps over success
        goto skip_success;

    printf(SUCCESS);        // dead code — never reached

skip_success:
    if (b != 10)            // ALWAYS false → never jumps
        goto skip_failure;

    printf(FAILURE);        // always printed

skip_failure:
    return a;               // return 0
}

The program sets b = 10 and immediately compares it to 10. The first branch is always taken, vaulting over the success print. The second branch is never taken, so the failure print always runs. There is no user input and no way to "pass" — the outcome is hardwired at compile time.

Key Takeaways

  • The full reverse engineering loop — load binary → disassemble → annotate instructions → reconstruct source — is the same regardless of crackme complexity. This one just makes every step short.
  • endbr64 is a Control-flow Enforcement Technology (CET) marker. It has no effect on the program's logic and can be skipped during analysis.
  • The x86-64 System V ABI requires zeroing %al before a variadic call (like printf) to indicate no floating-point register arguments are being passed.
  • Dead code — branches that can never be reached — is something to watch for. The compiler or author may have intentionally or accidentally left it; it still needs to be identified so you don't chase non-existent logic paths.

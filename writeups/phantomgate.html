PhantomGate v1.0

📅 May 2026 🏆 crackmes.one — AdminX 🔖 Reverse Engineering

Overview

PhantomGate is a serial-based crackme. The main job here was to understand how the four input groups were converted into numbers, then solve the final check to recover a working serial.

The program expects this format: 

XXXXX-XXXXX-XXXXX-XXXXX

A working serial:

4QJCG-P4R7Y-3VMY7-XRWHM

Step 1 — Anti-Debug Check

The crackme has an anti-debug trick that quietly corrupts the parsed input if a debugger is present. I stayed in static analysis so the values would not be altered.

Step 2 — Parsing the Serial

The serial is split into four 5-character groups using the dashes as separators. 

group0 - group1 - group2 - group3

Each group is converted with this custom alphabet: 

ACDEFGHJKLMNPQRTUVWXY3479

In practice, that means each group is treated like a base-25 value. 

value = value * 25 + index

Step 3 — Reduce the Final Check

After parsing, the program sends the four numbers into a small virtual machine. Instead of following every VM instruction forever, I reduced the check down to one final expression: 

target = 0x02D8EEC79A0331D6

v4 = (n0 * 2654435769) ^ n1
v5 = ror64(v4, 17) + n2
v6 = v5 ^ (n3 * 1818371886)
v7 = v6 ^ 2882400001

assert v7 == target   # all arithmetic mod 2^64

Step 4 — Solving with Z3

Once the check was reduced to one equation, I used Z3 to solve for a valid set of four group values and then converted those numbers back into the serial format. 

4QJCG-P4R7Y-3VMY7-XRWHM

That serial passes the check successfully.

Key Takeaways

  • Break the problem into stages: format, parsing, final check, then solve.
  • When a VM is only hiding one equation, simplifying it first saves a lot of time.
  • Constraint solvers are useful once the important validation logic is isolated.

Tools Used

  • IDA Pro (static analysis, VM tracing)
  • Z3 (Python bindings — constraint solving)
